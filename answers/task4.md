# Task 4：思考题

## 1. Make 和简单的 build.sh 有什么区别？

build.sh 每次运行都会依次执行所有命令，且构建逻辑需要手动编写、难以管理，只适合小型项目的练手和原型验证；

而 Make 每次只重建过期（失效）的目标：它根据 Makefile 中声明的依赖关系自动追踪源文件的变化，只重新编译受影响的部分，规则声明式、结构清晰，适用于正式项目。


## 2. CMake 是编译器吗？

执行 `cmake --build build` 时，最终是谁在编译 C 源文件？

CMake 不是编译器

CMake 在配置阶段（`cmake -S . -B build`）根据 CMakeLists.txt 生成 Makefile 等构建文件；
执行 `cmake --build build` 时，实际是调用 make，由 make 读取生成的构建文件，根据依赖关系判断哪些文件需要重新编译；
最终由 GCC / Clang 这些编译器完成 .c → .o 的编译，并将各个 .o 链接为可执行文件

## 3. 为什么不希望每次都重新编译所有 `.c` 文件？

降低时间成本。

只修改了一个 .c 文件时，受影响的只是它对应的目标文件，其余源文件的编译结果依然有效；如果每次都全部重编，哪怕只改一行代码，也要把几百上千个源文件重新编译一遍，大型项目的全量编译可能耗时几十分钟甚至更久。

而增量编译只需重编受影响的文件再重新链接，通常几秒到几十秒即可完成，大大缩短了开发中"修改 → 编译 → 运行/调试"的循环周期。Make / CMake 正是通过对比文件时间戳、追踪依赖关系来判断哪些目标已过期，只重编这些过期的文件，从而节省大量的时间成本。
